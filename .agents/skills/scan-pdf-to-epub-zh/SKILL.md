# 扫描 PDF 转可重排 EPUB

## 目标

将扫描版或图片型 PDF 制作成可搜索、可调字号、可追溯的 EPUB，同时让每一页、每张图片、每个编辑决定和每项验收结果都能回查到原扫描。原 PDF 必须作为不可变的本地来源；OCR 只能生成候选，不能直接充当证据。

## 工作约束

- 原 PDF 只读：不要覆盖、重新保存、上传或公开。
- 在独立项目目录中工作，至少维护 src/、work/、tools/、逐页 book-manifest.json 和人工可读的 QA 报告。
- 保留原始 OCR JSON、候选文本、精校逐页文本、图片来源和修复记录。
- 保留封面、书名页、版权页、插图、二维码、标志、空白页和纸书页码锚点。
- 说明可重排 EPUB 保留的是可搜索正文和图片，不是 PDF 在所有字号和屏幕宽度下的精确页面布局。
- 不翻译、不润色、不顺语义、不根据上下文补写扫描中没有的文字。
- 不把 OCR 置信度、模型相似度或语言模型的通顺程度当作字符准确率。
- 改动原 PDF、上传内容、公开版权页或替用户裁决重要歧义前必须暂停确认。
- 如平台不是 macOS，要如实说明 Apple Vision 不可用；不能声称完成了任一路线中的 Apple Vision 对照。

## 工作流程

### 1. 先审计，再处理

开始前读取已有项目文档、脚本、manifest、OCR、精校稿和 QA 证据。能复用就增量修复，不要无理由从第一页重做。

记录原 PDF 路径、文件大小、SHA-256、页数、页面尺寸、旋转、文字层、书签、语言、书名、作者、转换策略、输出目录和目标阅读器。先说明已经完成的部分和缺失的证据。

在全文 OCR 前先输出：

1. PDF 页数以及单页/双页分布。
2. 预估纸书页范围和特殊页清单。
3. 当前已有文件和可复用脚本。
4. 预计生成的目录和 QA 证据。
5. 需要确认的书名、语言/字形保留、繁简策略和页面歧义。

书名、语言或繁简策略存在实质歧义时，未经确认不要启动全书 OCR。

### 2. 建立 manifest 和视觉清点

在生成最终文本前创建或修复 book-manifest.json。为每个 PDF 页分配稳定 ID，并使用 extracted、ocr-complete、proofed、illustration-ready、confirmed-blank 等状态。

每页至少记录：

- PDF 页码和物理版式（single 或 spread）。
- 原图尺寸、旋转、来源哈希和裁切框。
- 双页按本页实际书脊确定的 gutter 位置。
- 左右纸书页码、章节和特殊页类型。
- 原图、OCR 图、Vision JSON、PaddleOCR JSON、候选文本、最终文本和 QA 证据路径。
- 插图在 EPUB 中的位置和简短替代文字。

先看缩略图或 contact sheet，登记封面、书脊、作者页、题记、书名页、版权页、章首、插图、广告、空白分隔页和后记。每个原 PDF 页必须对应最终正文、保留的特殊页/插图，或明确确认的空白页。

不要对所有双页使用固定 50/50 裁切。依据本页暗带、空白带或文字边界估计书脊，并保存每页裁切参数。

### 3. 选择一条 OCR 获取路线并保留证据

全文处理前必须选择并记录一条 PaddleOCR 路线：

- **路线 A——本地 PP-OCRv6 medium：**只启动一个项目管理的本地 PaddleOCR pipeline。在 macOS 上，将其结果与 Apple Vision 对照；在非 macOS 上，先完成 PP-OCRv6 medium 候选，说明 Apple Vision 不可用，再询问用户是否要增加另一个当前可用的 OCR 后端进行对照。用户若拒绝，则使用单候选继续对照扫描件视觉精校。所有本地引擎使用同一批图片、分辨率、裁切结果和 page ID；分别保留原始 JSON，并记录文字、置信度、坐标、阅读顺序、包/版本、模型、选项和图片哈希。
- **路线 B——用户已提供 AI Studio 结果：**如果用户已经提供该来源的官方 PaddleOCR AI Studio `.md` 和 `.json`，直接把它们作为 PaddleOCR 候选，不要为了重现结果而安装或运行本地 PaddleOCR。在 macOS 上，对映射后的源页运行 Apple Vision，并与 AI Studio 结果对照；在非 macOS 上，说明 Apple Vision 不可用，再询问用户是否要增加另一个当前可用的 OCR 后端。用户若拒绝，则使用已提供的候选继续对照扫描件视觉精校。记录来源、可取得的导出元数据、文件哈希和完整 PDF 页对应关系。

在 macOS 的两条路线中，都按项目声明使用 Apple Vision，常见设置为 zh-Hans、en-US、ja-JP、accurate 和 language correction。路线 A 处理中文扫描版或图片型 PDF 时，要求 PaddleOCR 3.7 或更高版本，并使用 PP-OCRv6 medium 检测与识别（`PP-OCRv6_medium_det` + `PP-OCRv6_medium_rec`）。不能静默把 Tesseract 或其他后端当作 Apple Vision 或 PaddleOCR 的等价替代。PaddleOCR-VL 或其他引擎必须按实际来源标注。

全文处理前必须建立 `work/ocr/engine-preflight.json` 并记录所选路线。为每个可用引擎或外部导出记录来源、适用时的包/版本、已知模型、语言、设备、选项、输入页数与哈希规则、缓存/下载状态、运行状态、输出路径、失败原因和起止时间。如果路线 A 和路线 B 都不可用，必须暂停并报告具体阻塞原因。本地 PaddleOCR 路径为空或缺少原始 JSON，属于路线 A preflight 失败；只有在路线 B 已记录 `.md`/`.json` 路径、来源、哈希和页面对应关系时，才可以接受。

路线 A 不应顺带下载无关流水线：除非基准或用户明确需要，否则关闭文档方向分类、文档矫正和文本行方向分类。每个任务只使用一个项目管理的 PaddleOCR 环境和一个 OCR pipeline 实例，复用模型缓存，不重复下载或初始化副本，并限制 batch/worker 数量，使内存占用可预期。subagent 可以复核页面或盲录样本，但不能启动另一套 PaddleOCR runner。

全文处理前先做代表性基准集。在 macOS 上，将 Apple Vision 与路线 A 的本地 PP-OCRv6 medium 结果或路线 B 的 AI Studio 结果对照。在非 macOS 上，先取得所选路线的 PaddleOCR 候选，再询问一次是否增加另一个当前可用的 OCR 后端；用户拒绝时不得阻塞后续视觉精校。多个本地引擎必须使用同一批图片、分辨率、裁切结果和 page ID；根据本书实际版式和错误模式决定主候选。两条路线的样本都应覆盖普通正文、对白密集页、章首、低对比/装订阴影页、中英日数字混排页、版权/书目信息页和插图邻接页。

对于不敏感的 PDF，用户可以上传到[官方 PaddleOCR AI Studio](https://aistudio.baidu.com/paddleocr)，调用在线旗舰分析，下载生成的 `.md` 和 `.json` 后把路径告诉 Codex，并按路线 B 处理。不要上传私人、机密或未经授权的内容，也不能把在线结果称为本地 PaddleOCR 已运行。

### 4. 用差异路由视觉核校

比较时只做明确允许的统一：Unicode NFC、换行和首尾空白。通过字符差异和行差异定位风险页、漏行、重行、顺序颠倒、标点分歧以及数字/网址分歧。

不要自动选择最长文本、最高置信度文本或最通顺文本。打开高清扫描，逐行裁决，将结果冻结到 final-pages/，并把可复现的修复写进脚本或修复日志。

优先复核人名、地名、标题、日文、引号和嵌套引号、省略号、破折号、数字、ISBN、网址、章节边界、书脊附近文字、跨页段落、对白和插图邻页。

特殊页优先使用“完整扫描图 + 可搜索转录”。原页面中的书法、标志、条码、二维码和有意义的图片文字仍应作为图片保留。

### 5. 正确使用 subagent

只有在用户允许并行工作后才调用 subagent。适合的工作包括：只看扫描图的盲录、独立复核风险页、检查双页拆分和阅读顺序、阅读 QA 结果并列出问题。不得让 subagent 启动重复的 OCR 环境或重复的模型实例。

盲录者不能看到 OCR、其他人的转录或已经冻结的精校稿。要求 subagent 只返回页码、转录、差异清单和视觉证据；主 agent 是源文件、manifest、最终文本、EPUB 和交付报告的唯一写入者。

如果盲录存在页码归属、覆盖范围或转录有效性问题，就不能把它称为金标准。

### 6. 从冻结源稿构建 EPUB

只有在最终文本和图片位置冻结后才构建 EPUB。必须从 manifest 和源文件生成，不能只手工修改压缩包里的 XHTML。

- 每章或语义区段使用独立、可维护的 XHTML。
- 每章包含可见的 <h1>、稳定标题 ID、语义结构和纸书页锚点。
- OPF spine、nav.xhtml 和兼容 toc.ncx 顺序一致。
- 封面同时声明 EPUB 3 cover-image、旧式 cover 元数据及必要的 guide 兼容声明。
- 保留正文 pagebreak 锚点；除非用户明确需要，不公开 page-list。
- 正文必须可搜索、可调字号，不锁定字体，也不要把全部文字烘焙进图片。
- 目录条目在兼容性需要时使用块级元素，确保逐条换行。

### 7. 验收和报告

按项目范围运行：

1. ZIP 和 mimetype 检查。
2. container、OPF 资源、内部链接、图片、标题、spine 和页锚点检查。
3. EPUBCheck 5.3.0 或项目声明的版本。
4. 章节独特短语、漏章、重复段落和页码顺序搜索。
5. Apple Books、微信读书等目标阅读器的实机 smoke test。
6. 不同屏幕宽度、字号、行距、浅色/深色背景、章首和插图页面的视觉检查。

报告中区分源/成品哈希、页覆盖、图片来源、引擎版本与差异风险、人工修订范围、机器检查、阅读器结果、未解决风险和 CER 证据。结构合法、人工视觉校对和独立金标准 CER 是三种不同结论。

没有有效的独立金标准时，明确写“未取得正式 CER 认证”。不要用置信度或候选相似度替代 CER。

## 必须请求确认的节点

遇到以下情况暂停：

- 扫描书名页与用户给定书名/作者不一致。
- 繁简转换可能改变专名、日文、标题或出版信息。
- 无法判断某页是空白、插图、漏扫还是拆分页。
- 扫描有遮挡，无法凭字形证据确认。
- 需要修改、上传、公开原扫描页或完整 OCR。
- 封面/封底裁切将不同于原扫描。
- 全局替换规则来自语义猜测而非扫描证据。

建立目录、缓存中间文件、安装已声明的本地依赖、运行检查和重建生成物，属于普通实现步骤，可以直接继续。
